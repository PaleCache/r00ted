Setting up R00TED.

Everything you need to clone, configure, and run your own server, plus how the bots work. This is a self hosted platform, you own the machine, so a few steps are on you.

On this page
Requirements Installation Configuration Reverse Proxy File Permissions Running the Server Desktop App Bots Support Development

01 Requirements

R00TED is self-hosted, so a few things need to already exist on your machine before install.

OSLinux (recommended)
RuntimeNode.js with npm installed
Reverse proxyNginx (or similar)
VoiceA working Jitsi Meet instance - can be your own or a public one that has email login disabled
DomainA domain or subdomain (DuckDNS works) for HTTPS
PatienceI cant help with that :)
Note: a domain is technically optional with some changes, but you'll need one to get HTTPS working properly. (You should use one, it's easy are free if you use something like duckdns etc)

02 Installation

Clone the repo and install dependencies.

bash
# clone the repository
git clone https://github.com/palecache/r00ted.git
cd r00ted
npm install

03 Configuration

Before starting the server, configure the following files:

  • config/server-config.json
  • app/configs/appconfig.json - desktop app only
  • Jitsi Meet Info - for public ones you only need their config to get the required info (ex. https://example.com/config.js) , or just host you own and get that info from your config
chatPassword is a single shared password, anyone who knows it can join your server. Treat it like a key, not a username/password pair.
  • klipyApiKey - The api key from klipy (currently using a testing one).
  • chatPassword - The password users will need to join the server.
  • kickTokenPath - The api key from kick.com saved in a json file like so {token: key_here}
  • streamerConfigPath - Points to the stream list file that is provided in the source already.
  • serverBanner - Points to the server banner, you can change it to whatever you like or use the provided one.
  • botPassword - The password the bot will use to connect.
  • backgroundImageUrl - Points to the default background image, you can change it to whatever you like or use the provided one.
  • loginImageUrl - Points to the login page image, you can change it to whatever you like or use the provided one.
  • pingdomain - This is the domain the clients will ping to get voice call ping display.
  • servericon - The server icon, used for the developer badge. It looks for r00ted.png in the public folder.
  • domain - The jitsi meet domain (ex. mysite), no .com or ports etc, just the actual domain.
  • embeddomain - The domain for the embed voice call if you want to use one (ex. example.com, no https). It embeds the jitsi call in r00ted (requires crossorigin rules to allow embed).
  • externalApiUrl - Link to your jitsi meet external api https://example.com/external_api.js (required for voice calls).
  • libJitsiUrl - Link to your jitsi meet lib (ex. https://example.com/libs/lib-jitsi-meet.min.js) (required for voice calls).
  • roomName - The name used when creating the embed room (anything you like).
  • bosh - Link to your jitsi meet's bosh (ex. https://example.com/http-bind).
  • muc - Link to your jitsi meet's muc (ex. conference.example.com).
  • focusUserJid - Link to your jitsi meet's focus user jid (ex. focus@conference.mydomain).
  • p2pEnabled - Sets peer to peer (enabled or disabled).
  • startAudioOnly - Sets whether a user should only have audio (no automatic video) when they join.
  • startWithAudioMuted - Sets if the user should be muted automatically when they join.
  • startWithVideoMuted - Sets if the user's video should be automatically disabled on join.
  • constraints - Screen share settings.
r00ted server config /r00ted/config/server-config.json
{
  "klipyApiKey": "key here", 
  "chatPassword": "chatpasswordhere",
  "kickTokenPath": "path to kick api key here should be stored in json example {token: key_here}",
  "streamerConfigPath": "./config/streamers-config.json",
  "serverBanner": "/backgrounds/r00ted-banner.png",
  "botPassword": "your_bot_password_here",

04 Reverse Proxy (Nginx)

R00TED only listens on 127.0.0.1:5350, so it is not directly reachable from the internet. Put Nginx in front of it and terminate HTTPS there.

Replace yourdomain.example.com and /path/to/r00ted with your own values before using this.

nginx · /etc/nginx/sites-available/r00ted
server {
    charset utf-8;
    listen 443 ssl;
    server_name yourdomain.example.com;
    client_max_body_size 200M;

    ssl_certificate /etc/letsencrypt/live/yourdomain.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/yourdomain.example.com/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers off;

    root /path/to/r00ted/public;
    index index.html;

    location / {
        try_files $uri @proxy;
    }

    location /uploads/ {
        alias /path/to/r00ted/uploads/;
        expires 30d;
        access_log off;
        client_max_body_size 200M;
    }

    location /avatars/ {
        alias /path/to/r00ted/public/avatars/;
        expires 30d;
        access_log off;
    }

    location @proxy {
        proxy_pass http://127.0.0.1:5350;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 86400;
        proxy_send_timeout 86400;
        proxy_buffering off;
    }

    location = /login {
        proxy_pass http://127.0.0.1:5350/login;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location = /upload-image {
        client_max_body_size 200M;
        proxy_pass http://127.0.0.1:5350/upload-image;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location = /upload-avatar {
        client_max_body_size 200M;
        proxy_pass http://127.0.0.1:5350/upload-avatar;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location = /upload-emote {
        client_max_body_size 10M;
        proxy_pass http://127.0.0.1:5350/upload-emote;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Cookie $http_cookie;
    }

    location ~ ^/delete-emote/ {
        proxy_pass http://127.0.0.1:5350;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Cookie $http_cookie;
    }

    location /ws/ {
        proxy_pass http://127.0.0.1:5350/ws/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 86400;
        proxy_send_timeout 86400;
        proxy_buffering off;
    }
}

server {
    listen 80;
    server_name yourdomain.example.com;
    return 301 https://$host$request_uri;
}

After saving, verify and reload:

bash
sudo nginx -t
sudo systemctl reload nginx

05 File Permissions

After installing, or whenever permissions get out of sync, run this from the project root.

bash
find uploads -type d -exec chmod 750 {} \;
find uploads -type f -exec chmod 640 {} \;

find public/avatars -type d -exec chmod 755 {} \;
find public/avatars -type f -exec chmod 644 {} \;

find public -type d -exec chmod 755 {} \;
find public -type f -exec chmod 644 {} \;

chmod 700 config
chmod 600 config/*.json

chmod 700 data
chmod 600 data/*.json

Why these permissions?

PathModeWhy
uploads/750 / 640Uploaded images & videos. Never need to be executable.
public/avatars/755 / 644Publicly served avatars & custom emotes.
public/755 / 644Frontend app files, not user data.
config/700 / 600Chat password, bot password, API keys. Owner-only.
data/700 / 600Accounts, messages, playlists, roles, channels. Owner-only.
Run these as the user that owns the project, or with sudo. Getting Operation not permitted? Check ownership first with ls -l uploads/<file>, then chown or rerun with sudo as needed. If you change which user runs the Node process, rerun the permission commands.

06 Running the Server

Start the server from the project directory.

bash
node server.js
For production, run R00TED under a process manager like PM2 or a systemd service so it survives terminal sessions and reboots.

07 Building the Desktop App

Build on the target OS, use Linux to build Linux binaries, Windows to build Windows binaries. Use a VM if needed.

Linux

bash
npx electron-builder --linux --publish=never

Windows

bash
npx electron-builder --win --publish=never
